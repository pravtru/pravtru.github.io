# pravtru.github.io

Статический сайт на GitHub Pages — генератор графических элементов инженерной/электротехнической документации по ГОСТ (со ссылкой на СП 333.1325800.2020 для формирования IFC-моделей). Без build-процесса и фреймворков: чистые HTML/JS/XML.

## Структура проекта

- **`index.htm`** — стартовая страница-описание с картой понятий: *Объект → Раздел → Модуль → Элемент → Блок*.
- **`View.html`** — движок рендеринга. Через `?name=XXX` в URL подгружает `XXX.xml`, рекурсивно разворачивает вложенные `<Bl>`/`<Bl0>` (заменяя их содержимым соответствующего XML-файла с подстановкой параметров по `id`/`bid`), выводит итоговый SVG и исходный код на странице. Если в файле несколько тегов `<svg>`, они показываются постранично (кнопки «Назад»/«Вперёд», индикатор страницы с атрибутом `tip`), а не все сразу.
- **`Ob.htm` / `Mdl.htm` / `El.htm` / `Blok.htm`** — описания понятий "Объект", "Модуль", "Элемент" и "Блок", каждое дополнено таблицей-каталогом всех соответствующих XML-файлов со ссылкой "Просмотреть" (`View.html?name=...`) для предпросмотра.
- **XML-файлы в корне проекта** — библиотека графических элементов, разбитая на четыре типа: **Элементы** (`<El>`, каталог в `El.htm`), **Модули** (`<Mdl>`, каталог в `Mdl.htm`) — составная часть объекта из нескольких элементов, **Блоки** (`<Bl>`, каталог в `Blok.htm`) и **Объекты** (записи `<project>` внутри `Projects.xml`, каталог в `Ob.htm`). Полный список — см. ниже.
- **`bootstrap.min.css` / `bootstrap.bundle.min.js`** — вендорные библиотеки для UI (модальные окна выбора модели/параметров в `View.html`).

## Перенос блоков из БД `pravt` (таблица `Bloki`)

На локальном SQL Server есть база `pravt` с таблицей `Bloki` (166 строк, колонки `ID`, `Name`, `XML`, `User`) — более ранняя/параллельная версия этого проекта на собственном векторном DSL (`<Blok Name>`, `<Line Width><Pt X Y H W/></Line>`, `<Arc X Y R sAng Ang/>`, `<Text Size Aligned X Y P R Wmax/>`, ссылки на другие блоки `<Blok ID=N X Y><P ID=M>...</P></Blok>`, условные варианты `<If P="0"><eq>N</eq><Then>...</Then></If>`).

Правила пересчёта в текущий SVG-формат:
- координаты: старая система Y вверх (математическая), SVG — Y вниз → **все Y меняются знаком** (`svg_y = -old_y`);
- `<Line>`/`<Pt>` → `<line>`/`<polyline>`/`<rect>` (или `<polygon fill="#000">`, если исходная толстая линия явно рисует закрашенную фигуru — стрелки, треугольники);
- `<Arc X Y R>` (без sAng/Ang) → `<circle r="R">`; `<Arc ... sAng Ang>` (везде встречались только полуокружности) → приближение квадратичной кривой Безье;
- `<Text ... P="N">` → `id="N"` (цель для `<Pr bid="N">`); `R="90"` → `transform="rotate(-90 x y)"`; `AlY="1"` → `dominant-baseline="middle"`;
- `<Blok ID="N" X Y><P ID="M">текст</P></Blok>` → `<g transform="translate(X Y)"><Bl Name="ИмяПоID"><Pr bid="M">текст</Pr></Bl></g>`.

166 строк делятся на 3 категории: ~120 простых графических блоков, ~22 блока со встроенным `<Script>` (JS, динамически строит форму параметров и генерирует схему — прямого аналога в текущей статической системе нет, не переносились), ~20 блоков с именами-числами (`"5"`…`"23"`) — сохранённые листы конкретного проекта, а не переиспользуемые шаблоны.

Перенос простых блоков и блоков-чисел завершён (94 файла, все без `<Script>`):
- **Первая партия (16 файлов)**: `Klemma.xml`, `KlemmaWide.xml`, `ChainNumber.xml`, `Rele_Time.xml`, `Perekl2.xml`, `Perekl3.xml`, `PriborSA.xml`, `NasosSA.xml`, `TreugolnikSA.xml`, `VozvratnikSA.xml`, `AI_SA.xml`, `DI_SA.xml`, `Ethernet_SA.xml`, `Zadvizhka.xml`, `UPS.xml`, `PLC_Rele.xml`.
- **Вторая партия (78 файлов)** — перенесена автоматическим конвертером (PowerShell-скрипт, читает `Bloki` через `SqlClient`, пересчитывает координаты/повороты по правилам выше, разрешает вложенные `<Blok ID=N>` через таблицу соответствия ID→имя файла): приводы и реверсивный привод (`Привод.xml`, `Реверсивный привод.xml`, `Силовая часть реверсивного привода.xml`, `Концевые выключатели Auma.xml`, `Диаграмма Auma.xml`, `Привод с переключателем.xml`, `Переключатель 1 контакт.xml`, `КМ горизонтально.xml`), управление задвижкой (10 файлов), схемы автоматизации насосной/камеры/тепловой камеры (14 файлов), АВР (5 файлов), штампы/спецификации/ведомости (11 файлов), схемы внешних связей (4 файла), прочие схемы (6 файлов: `Цепь кабеля.xml`, тепловычислители, `С2000-КПБ.xml`, `Меркор. Принципиалка.xml`, `Независимый расцепитель.xml`), и 19 листов-снимков конкретного проекта (`5.xml`…`23.xml`, кроме `21`→заменён на `21.xml` без строки-дубликата). Полный список — в `Blok.htm`.
- Дубликаты с одинаковым `Name` в БД (например, несколько версий «Ведомость чертежей» или «Схема внешних») схлопнуты в один файл — оставлен вариант с наибольшим объёмом XML.
- Блоки со `<Script>` (генераторы целых листов с формами параметров) не переносились — статическому шаблонизатору `View.html` нужен готовый SVG, а не JS-генератор.

## Механизм подстановки блоков

Блок вызывается с параметрами, например:

```xml
<Bl Name="XT1"><Pr bid="1" transform="translate(0 0) rotate(0 0 0)"></Pr></Bl>
```

`View.html` рекурсивно ищет в вызываемом блоке элементы с атрибутом `id`, совпадающим с `bid` переданного параметра `<Pr>`, и заменяет их атрибуты/содержимое — то есть это самодельный шаблонизатор для SVG на чистом JS без зависимостей.
